COMPLETE FOLLOW-THROUGH REQUEST — DO NOT LEAVE PRIOR OR NEW GAPS UNRESOLVED

This is the follow-through request after the latest #371/#372/#373/#374 campaign results. Treat ALL previous requirements, newly discovered roots, partials, blockers, and next steps as one reconciled worklist.

0. PRIMARY RULE

Do NOT stop at the latest reported success.

Re-read and reconcile:

  • MASTER CONTINUATION — Independent verification #364–#369 + full execution #370 #371
  • SUPPLEMENTARY DEEP ROOT-CAUSE CLOSEOUT — 330-point black/white/partial/load audit #372
  • ENV-PREREQUISITES — Android API / CPU / ABI / hardware / software compatibility matrix #373
  • BASE-ANDROID — Complete Android Platform Contract Foundation Audit #374
  • current constitution/laws
  • root_registry.json
  • worklog/campaign state
  • all posted evidence ledgers
  • current source tree
  • current HEAD
  • existing historical evidence

Then derive one complete matrix:
DONE / VERIFIED / PARTIAL / BLOCKED / PENDING / UNKNOWN / DUPLICATE / SUPERSEDED.

Every incomplete item must either be implemented and verified, or be proven to require an external prerequisite and recorded as BLOCKED with evidence.

Do not create duplicate roots.

1. FIRST REPRODUCE CURRENT BASELINE

Before changing code:

  • verify current remote HEAD
  • verify current binary SHA
  • verify source/build reproducibility
  • run the recorded baseline gates
  • verify anchors/goldens
  • verify Gate A
  • verify negatives
  • verify reinstall/uninstall
  • verify battery
  • verify NATX 10/10 x3
  • verify multi-app
  • record any drift before debugging.

No regression may be hidden.

2. COMPLETE #374 — ANDROID BASE FOUNDATION

Execute the entire #374 98-section foundation contract, not merely its documentation.

For every domain prove:
SOURCE -> ANDROID LAW -> IMPLEMENTATION -> SYNTHETIC POSITIVE -> SYNTHETIC NEGATIVE -> REAL APK -> FIRST DIVERGENCE -> 3 RUNS -> REGRESSION.

Audit all previous #374 layers including:

  • platform/device contract
  • API/target-SDK behavior
  • CPU/ABI/native/linker
  • APK/package/install/update/splits/signing
  • permissions/AppOps/special access
  • UID/user/profile/sandbox/security
  • filesystem/CE/DE/external/scoped storage/SAF/MediaStore
  • Context/ContextImpl
  • system services and boot/readiness ordering
  • Binder/IPC identity
  • lifecycle/process/application/provider startup
  • Intent resolution/package visibility
  • resources/configuration/overlays
  • Looper/threading/memory
  • Window/View/Display/IME/System UI
  • Surface/BufferQueue/RenderThread/Skia/compositor/presentation/capture
  • input routing
  • network/netd/DNS/TLS/VPN
  • media/audio/camera/sensors/location
  • SQLite
  • crypto/Keystore
  • SELinux/MAC/security boundaries
  • alarms/jobs/notifications/foreground/background policy
  • backup/restore/clear-data/force-stop/reinstall/update
  • accessibility/autofill/text services
  • clipboard/share/chooser
  • settings/system configuration
  • widgets/shortcuts/launcher
  • exceptions/ANR/watchdog
  • observability
  • corpus-derived discovery
  • reference differential probes.

Do not count placeholders as VERIFIED.

3. CLOSE CURRENTLY KNOWN PARTIALS

R-NEW-464

Finish the Method-record reflection/getDeclaredMethods route deterministically.

  • Do not use broad reflection hacks.
  • Preserve declaring-class identity and method metadata.
  • Verify getDeclaredMethods/getModifiers/getAnnotation and related Method semantics.
  • Add focused synthetic probes and a real APK.
  • 3 clean runs.
  • Cross-match registry before adding any new root.

ViewPager / mCurItem

Resolve the primitive/field identity frontier if the APK is available and SHA-pinned.

  • First establish exact APK identity.
  • If current F-Droid artifact differs from recorded evidence, do NOT claim a runtime regression.
  • Obtain/restore the exact evidence artifact through the existing reproducible corpus mechanism if available.
  • Then reproduce and fix the generic law.
  • No ViewPager-specific hack.

Compose family / F-NEW-221

Use sudokusolver and another independent Compose APK.

  • determine the actual missing platform/runtime contract
  • distinguish Compose infrastructure from app-specific code
  • fix generic contract only
  • verify fan-out on another Compose app.

Fragment materialization frontier

For ARM/native and mixed apps, separate:
ABI blocker
from
Fragment/component/lifecycle blocker.
Do not report a dual-cause without independent A/B evidence.

F-NEW-084 interpreter halt

Investigate the infinite-loop cap 50001.

  • determine whether the interpreter loop is semantically legitimate, incorrectly bounded, or missing a runtime operation
  • never simply raise/remove the cap to make the game pass
  • add a bounded semantic execution law and regression probe
  • test fairymahjong plus another game.

4. ENVIRONMENT / PREREQUISITE LAYER

Complete #373 into an operational preflight gate.

For every APK inspect:

  • min/target/max SDK
  • target-SDK behavior changes
  • permissions + AppOps/special access
  • features
  • graphics requirements
  • Vulkan/GLES requirements
  • native ABIs per ELF
  • DT_NEEDED dependency closure
  • WebView
  • media codecs
  • camera/mic/location/sensors
  • storage model
  • providers/content authorities
  • external dependencies
  • splits
  • required services.

Return:
AVAILABLE / PARTIAL / MISSING / INCOMPATIBLE / NOT_TESTED
and
REQUIRED / OPTIONAL / CONDITIONAL / IMPLIED / UNKNOWN.

The gate must run BEFORE ordinary runtime debugging.

5. CAPABILITY HONESTY

Audit every advertised capability against actual execution.

In particular:

  • SUPPORTED_ABIS must not advertise non-executable ARM unless translation exists.
  • Vulkan must not be advertised if only GLES2 exists.
  • camera/GPS/telephony/BT/NFC must remain honestly absent unless implemented.
  • permissions must not all become granted.
  • services must not return fake success.
  • Build.* and feature flags must match behavior.
  • storage paths must correspond to real storage.
  • native libraries must be executable, not merely extractable.

Produce a FALSE_ADVERTISED matrix and drive every false claim to zero or explicit documented limitation.

6. UNKNOWN APK GATE

Make the Agent Skill consume the same preflight contract.

For an unknown APK the skill must be able to answer:

  • what is this package?
  • what does it require?
  • what can MiniAndroid provide?
  • what is missing/incompatible?
  • what permissions are requested/granted/denied?
  • what ABI can execute?
  • what system services are needed?
  • what storage is accessible?
  • what graphics/media/input prerequisites exist?
  • what is the first blocker/divergence?
  • should this enter runtime root work?

Mandatory verdict:
PREFLIGHT_PASS / ENVIRONMENT_BLOCKED / INSTALL_BLOCKED / SECURITY_BLOCKED / IDENTITY_BLOCKED / SERVICE_BLOCKED / EXECUTION_BLOCKED / RESOURCE_BLOCKED / GRAPHICS_BLOCKED / MEDIA_BLOCKED / NETWORK_BLOCKED / INPUT_BLOCKED / CAPTURE_ONLY / RUNTIME_ROOT / UNKNOWN.

7. CORPUS-DERIVED DISCOVERY

Do not rely only on the predefined foundation list.

Mine the current corpus and representative new APKs for:

  • framework APIs
  • Java APIs
  • reflection
  • system services
  • permissions
  • intents
  • providers
  • URI schemes
  • MIME types
  • native libraries
  • ELF dependencies
  • graphics APIs
  • media codecs
  • SQLite
  • storage
  • crypto
  • scheduling
  • WebView
  • sensors/hardware.

Cluster failures by generic contract. One generic fix should fan out.

  • 1 genuinely new independent-family app
  • 1 genuinely new independent-family game
  • preferably a second app/game if the first exposes a major new frontier.

Do not select only known-good APKs.

For every candidate:

Before every new registry ID, search the entire registry and evidence history.

11. SECURITY / NEGATIVE TESTS

Prove denial semantics for:

  • permissions
  • signature permissions
  • AppOps
  • private storage
  • cross-package storage
  • wrong UID/user
  • unexported components
  • provider/path permissions
  • URI grants
  • PendingIntent identity
  • unsupported ABI
  • missing native library
  • unavailable service
  • unavailable hardware
  • unsupported API
  • incomplete split.

No universal root, universal permission, universal service or universal capability.

For at least 3 independent installed apps including a complex app:

  • install
  • verify package-owned directories
  • create real file
  • write real bytes
  • read bytes
  • stat/length
  • SharedPreferences
  • SQLite where used
  • media/assets where used
  • restart
  • verify persistence
  • clear data
  • verify expected removal
  • reinstall
  • verify expected reset/preserve semantics
  • uninstall
  • verify cleanup/isolation.

Path strings alone are not evidence.

13. VISUAL PROVENANCE

For white/black/partial results:
APK -> component -> ViewTree -> draw op -> surface -> buffer -> compositor/presentation -> capture.

Record the first stage that diverges.

A non-empty PNG is not success.
A ViewTree is not success.
EGL initialization is not success.

14. BASELINE / REGRESSION AFTER EACH GENERIC FIX

After every generic foundation fix:

  • focused synthetic probe
  • focused real APK
  • relevant random app/game
  • baseline battery
  • anchors/goldens
  • negatives
  • reinstall/uninstall
  • NATX if native path affected
  • 3 clean runs.

No batch of speculative changes without intermediate evidence.

15. SOURCE-FIRST RESEARCH REQUIREMENT

Before implementing a missing semantic law:

  1. locate Android/AOSP reference behavior
  2. identify actual source/algorithm
  3. write the semantic law
  4. identify current MiniAndroid divergence
  5. implement the smallest generic correction
  6. test positive + negative
  7. test real APK
  8. cross-match registry
  9. record evidence.

Do not infer platform semantics from one application's crash.

17. DEFINITION OF DONE

This campaign is complete only if:

  • MASTER CONTINUATION — Independent verification #364–#369 + full execution #370 #371 baseline remains green
  • SUPPLEMENTARY DEEP ROOT-CAUSE CLOSEOUT — 330-point black/white/partial/load audit #372 has zero duplicate roots
  • ENV-PREREQUISITES — Android API / CPU / ABI / hardware / software compatibility matrix #373 preflight is operational
  • BASE-ANDROID — Complete Android Platform Contract Foundation Audit #374 foundation domains are executed, not merely documented
  • current partial roots are resolved or externally blocked with evidence
  • environment blockers are separated from runtime roots
  • capability advertisements are honest
  • unknown APK gate works
  • at least one new app + one new game pass through the complete pipeline
  • persistence/security negative tests pass
  • visual first-divergence tracing works
  • 3 clean runs are green for the final binary
  • all evidence is committed and pushed
  • worklog/registry/issues are reconciled
  • remaining unknown surface is explicitly numbered.

Do not declare "complete" while any known PARTIAL/PENDING item above is merely deferred without a proven blocker.

18. IMPORTANT — DO NOT CHEAT THE BASE

Forbidden:

  • app-specific hacks
  • package-name conditionals
  • APK-specific constants

  • treating launch/process survival as success
  • treating screenshot existence as success
  • treating parser success as execution
  • treating one successful APK as foundation verification.
