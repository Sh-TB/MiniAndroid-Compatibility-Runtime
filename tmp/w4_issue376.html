EXTERNAL ROOT CENSUS — Deep multilingual root discovery for MiniAndroid

Mission

Create one authoritative, continuously updated census of generic Android compatibility/runtime root causes that can explain APK failure, white/black/partial screens, wrong UI, missing state, native failures, silent stalls, or false-positive execution.

This is NOT an APK-by-APK test list. Find root families already discovered by AOSP engineers, emulator projects, Waydroid/Anbox/Redroid/WSA, ART/Dalvik, graphics/runtime projects, AndroidX/Compose/WebView, app/framework issue trackers, academic work, Chinese/Russian/English/Japanese/Korean communities, GitHub issues/comments/PRs, source code, and technical forums — then map them to MiniAndroid.

CRITICAL: Do NOT make thousands of APKs rediscover the same root.

For every external finding:
SOURCE → mechanism → Android/AOSP semantic law → root family → MiniAndroid registry cross-match → NEW / DUPLICATE / ALREADY-FIXED / ENVIRONMENT-ONLY → representative probe/APK → A/B proof.

FOUR DEEP ROUNDS

ROUND 1 — AOSP/framework + major compatibility projects.
ROUND 2 — GitHub issue/PR/comment archaeology: Waydroid, Anbox, Redroid, WSA, emulator, ART, graphics, runtime, WebView, Compose, Flutter, Unity/Godot/libGDX.
ROUND 3 — multilingual: Chinese, Russian, Japanese, Korean, English; forums/blogs/source-reading communities and issue comments.
ROUND 4 — adversarial gap hunt: search specifically for root families missing from this census and challenge every P0/P1 assumption.

After EVERY round, update this same issue with:

  1. sources searched;
  2. new candidates;
  3. deduplication against MiniAndroid registry;
  4. priority/fan-out ranking;
  5. evidence quality;
  6. exact coder probes required.

Do not blindly recreate these:

  • StaticLayout.Builder
  • Space AT_MOST / weight semantics
  • field identity / instance-field aliasing
  • C013 placeholder/overpaint
  • resource provenance
  • Method-record reflection family
  • Method.getModifiers/getParameterTypes/getAnnotation
  • DEX annotation index decoding
  • getDeclaredMethods constructor filtering
  • ArrayList(Collection) / CollectionShadow
  • annotation-proxy access
  • LayerDrawable materialization/findDrawableByLayerId/getId/setId
  • XmlPullParser / Resources.getLayout
  • ShortcutInfo.Builder
  • Compose/deferred UI
  • Fragment materialization
  • ViewPager/mCurItem artifact frontier
  • F-NEW-084 progress-aware interpreter execution
  • Canvas(Bitmap) / Bitmap pixel semantics
  • AssetManager/resources
  • SharedPreferences
  • SQLite/WAL
  • package data root/filesystem containment
  • providers/Intent/BitmapFactory
  • TouchDispatcher
  • EGL facade/GL20
  • WebView JS-DATA-PASS
  • basic ABI/native execution gate
  • install/persistence provenance
  • lifecycle/window/root/deferred-UI family

These may still contain missing sub-roots; prove family completeness rather than assuming it.

P0 ROOT FAMILIES

P0-01 Window → ViewRoot → Surface → BufferQueue → presentation

Potential sub-roots:
Window creation/registration; WindowManager registration; ViewRoot creation; AttachInfo/root linkage; relayout; Surface allocation; BufferQueue producer/consumer; first buffer; acquire/release; EGLSurface; swap/present; compositor visibility/z-order; final presentation.

A ViewTree, successful draw, or process survival is NOT equivalent to presented pixels.

P0-02 CPU / ABI / ELF / native execution

APK ABI selection; ELF machine/class; dynamic linker; DT_NEEDED; relocations; JNI_OnLoad; dlsym/symbol resolution; translation availability/correctness; ANativeWindow/native graphics; native filesystem assumptions.

EXTRACTED is not EXECUTED.

P0-03 EGL/GLES/Vulkan capability and surface semantics

GLES version; EGL extensions; context; window surface; shader/compiler; texture/FBO limits; precision/GLSL; Vulkan feature mismatch; swap/present; AHardwareBuffer usage; software renderer; SurfaceFlinger/RenderEngine.

P0-04 ClassLoader / ClassLinker / identity / initialization

Parent loader chain; DEX search order; duplicate class identity; class/method/field/interface resolution; clinit execution; initialization state; reflection visibility; hidden API policy; class-loader-specific behavior.

P0-05 Binder / ServiceManager / system-service contract

Service registration/absence/restart; Binder identity; transaction code/version mismatch; Parcel schema; Parcelable version; permissions; oneway; death notification; lifecycle; system_server restart; boot-time service availability.

SERVICE EXISTS != SERVICE CONTRACT COMPATIBLE.

P0-06 Looper / MessageQueue / Choreographer / traversal

Thread affinity; Handler; queue ordering; barriers; delayed callbacks; Choreographer; vsync; frame callbacks; invalidate; requestLayout; traversal scheduling; measure/layout/draw never reached.

Especially important for Compose/deferred UI.

P0-07 WebView / renderer / storage dependency

Provider/backend; WebView package/version; renderer process/IPC; data directory; storage mount; cookies/local storage; asset loading; JS; DOM/CSS; network; TLS; GPU/WebGL; media-service dependencies.

P0-08 Storage / package data / SAF / MediaStore / providers

/data/user/0 vs user_de; UID ownership/isolation; external storage; Android/data/media/obb; scoped storage; SAF; MediaStore; ContentProvider; URI grants; MIME/path permissions; restart persistence; clear/reinstall/uninstall cleanup.

PATH STRING EXISTS != ANDROID STORAGE SEMANTICS.

P0-09 Permission / AppOps / UID / User identity

Manifest permission; runtime grant; AppOps; special access; UID; user/profile; signature permissions; service-side enforcement.

Do not globally grant permissions.

ROUND-1 HIGH-VALUE EXTERNAL SIGNALS

  1. AndroidGoLab/binder demonstrates about 1,500 Android Binder interfaces and version-aware transaction-code resolution; even firmware/API revisions can shift transaction mappings.
  2. Waydroid issue #1148 demonstrates intermittent black screen when launching an app directly while full UI works: session/window/compositor setup can be causal.
  3. Current Waydroid issues include graphics composer crashes, ARM/libndk translation, libhoudini/Vulkan deadlocks, zygote bootclasspath, ANativeWindow/AV1, camera and graphical corruption — high-value archaeology targets.
  4. Redroid issue #934 demonstrates SurfaceFlinger/SwiftShader/AHardwareBuffer failure during shader-cache warmup before ordinary app rendering.
  5. dotnet/android issue #12077 demonstrates API/system-image ↔ emulator-version contract failure: old emulator lacked required SurfaceFlinger AIDL and boot stalled/black-screened.
  6. dotnet/android issue #12119 demonstrates system_server restart causing package Binder service disappearance during install.
  7. Google Maps Compose issue #875 demonstrates missing ViewTreeLifecycleOwner can directly break ComposeView creation/measurement.
  8. Android API semantic-drift research reports thousands of Android API incompatibilities across releases; semantic differences must be treated as a major root source.

SOURCE CLASSES — SEARCH ALL

AOSP; Android Developers; source.android.com; CTS/VTS; CDD; ART/Dalvik; Android emulator; Waydroid issues/comments; Anbox; Redroid; WSA; AndroidRecomp; DroidVM; droidsaw; Skydnir; libarsc; bundletool; Robolectric; Paparazzi; Roborazzi; emulator harnesses; Chromium/WebView; Mesa/SwiftShader; Skia; ANGLE; EGL/GLES/Vulkan; Flutter Android; React Native Android; Compose/AndroidX; libGDX/Unity/Godot; SQLite; Bionic/linker; Binder/AIDL; Chinese; Russian; Japanese; Korean; Stack Overflow; Reddit; academic papers.

Search source code, closed issues, PR discussions, and COMMENTS — not only issue titles.

ROOT RECORD FORMAT

ROOT-ID | FAMILY | PRIORITY | LANGUAGE | SOURCE | SOURCE-TYPE | MECHANISM | ANDROID LAW | MINIANDROID CROSS-MATCH | EXISTING ROOT | FANOUT | WHITE/BLACK LINK | ENVIRONMENT/RUNTIME | CONFIDENCE | PROBE | REAL APK | STATUS | EVIDENCE | CODER ACTION

NO FALSE ROOTS

Do not promote package-specific, OEM-only, GMS-only, host-desktop-only, corrupted-APK, stale, already-fixed, or symptom-only findings without causal proof. Mark them APP-SPECIFIC / ENVIRONMENT-ONLY / STALE / UNPROVEN as appropriate.

PRIORITY

P0 = broad fan-out, lifecycle/framework initialization, native execution, presentation, storage, services, or can cause white/black/partial output.
P1 = substantial but narrower fan-out.
P2 = specialized.
