## This Round's Progress

### Primary fix: Multi-DEX class injection (Phase 1.2)

**Root cause of Phase M "class not in index" blocker:**
- `stage_parse_dex()` only parses `classes.dex` (DEX 0) into `result.dex_report`
- The other DEX files (classes2..classesN) were loaded into `per_dex_raw_data_` but
  their classes were NEVER merged into `dex_report.classes` and `class_info_index_`
- Only ONE class was injected on-demand (the manifest activity class)
- This means `class_info_index_` only contained DEX 0 classes. Any class defined
  in DEX 1+ (e.g. Telegram's UserConfig in classes3.dex) returned "class not in index"

**Generic fix:**
- Added `DalvikExecutionEngine::inject_secondary_dex_classes()` method that:
  1. Iterates over `per_dex_raw_data_[1..N-1]` (skips DEX 0)
  2. Parses each secondary DEX with `DexParser::parse_data()`
  3. For each class, checks `class_info_index_` for duplicates
  4. Appends to `dex_report_->classes` (via const_cast) and updates index
- Called from inside `execute_apk_with_activity()` right after `dex_report_` is set
- **Telegram: 28557 classes injected from 4 secondary DEX files**

### Additional fix: ConcurrentHashMap bypass

- `Lj$/util/concurrent/ConcurrentHashMap;.e` (computeIfAbsent) loops forever
- Without bypass, runtime hangs in `FastDateFormat.<clinit>` before reaching LoginActivity
- Added `Lj$/util/concurrent/ConcurrentHashMap;` AND `Ljava/util/concurrent/ConcurrentHashMap;`
  to framework-bypass list in `try_recursive_invoke`
- Generic fix — affects any APK using desugared Java 8 collections

### Verified secondary findings

1. **`this` receiver propagation** — Already fixed in primary branch (EXP-061 FIX)
2. **Secondary DEX lazy injection** — Root cause CONFIRMED, FIXED (see above)
3. **getInstance dispatch** — Same root cause as #2, fixed by inject_secondary_dex_classes()

See `docs/compatibility/SECONDARY_FORENSICS_INTEGRATION.md` for full details.
