## 4. Three corrections the honest-status work forced (all Confirmed on current main, fixed)

1. **GL_FRAGMENT_SHADER is 0x8B30 — the engine had NO fragment-shader type check at all.** The first family-gate patch assumed 0x8B32 (a value that exists in neither GLES2 nor desktop GL2); the real app sources created fragment shaders with 0x8B30 (→ PGL slot 343), the link law saw `nv=1 nf=0` and honestly refused every program. GLES2 law restored: 0x8B31 = vertex, 0x8B30 = fragment.
2. **gdx ShapeRenderer declares the varying `v_col`, not `v_color`** (source-verified from the app's own stored shader text, `evidence/gp583/ttt_shader_classification_glsldebug.log`). The family law now keys on the DECLARED varying name (any name, referenced in the body) instead of a hardcoded one.
3. **`#endif\nvarying vec4 v_col;` merged in the statement scan** (no `;` between them) — preprocessor lines are now dropped before analysis.
