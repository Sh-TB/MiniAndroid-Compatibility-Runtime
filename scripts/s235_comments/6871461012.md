**Application / Feature:** 2048 (`com.uberspot.a2048` v1.0) — WebView game: complete board render + interactive gameplay (touch input)
**Status:** VERIFIED for render (4×4 grid, tiles, score UI) and TESTED for interaction (touch-driven move/merge/score/spawn)

**What changed (runtime laws added — `src/webview/webview_engine.cpp`, `src/runtime/execution_engine.cpp`, `src/framework/android_shadows.h` + `.cpp`, `src/dex/dalvik_engine.cpp`, `src/webview/html_dom.h`):**
- **S134 CSS FLOAT law** (CSS 2.1 §9.5.1): `float:left/right` placement on a per-container float line, wrap rule, `clear`, and the container extent including the float bottom. Face: the board is `.grid-cell { float:left }` rows — before this law every cell stacked into a full-page vertical column.
- **S135 WORD-WRAP law** (CSS Text §5): greedy wrap over the styled run set (paragraphs with inline `<a>` wrap with per-run styles). Face: the intro painted one unbroken line past the viewport edge.
- **S136 STACKING law** (CSS 2.1 Appendix E): positioned descendants paint inside a z-given ancestor's stacking context (DOM order), not at a flat z. Face: tiles (z auto, inside `.tile-container` z2) painted at z0 UNDER `.grid-container` (z1) and the 0.35-alpha cells washed them off the board.
- **S137 BODY/CANVAS-BG law**: `body { margin: 80px 0 }` offsets the page box; the html/body background propagates to the canvas (#faf8ef warm paper).
- **S138 BORDER-BOX law** (CSS 2.1 §10.3.2): explicit `height` stores the OUTER height (padding counted) — the score boxes rendered 25px tall instead of 55px and their text fell below the box.
- **S139 KEY-EVENT law**: DOM KeyboardEvent contract (`which`/`keyCode`/`preventDefault`/modifiers) + WebView arm in `dispatch_key_event` (AOSP View.dispatchKeyEvent → Chromium DOM keydown).
- **S140 INTERACTION PROBE**: a post-first-paint swipe pair (LEFT, then UP) driven through the canonical `dispatch_touch_listener` pipeline (opt-in via `MINIANDROID_WEBVIEW_PROBE=1`; passive baselines stay byte-stable).
