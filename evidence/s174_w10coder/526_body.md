## KNOWLEDGE TRANSFER (for the main coder — how to think about these systems)

1. **The three-layer native stack (587+594+595):** a registered native must survive THREE gates to execute: (a) the dispatch layer must TRY it (F-C4-594: `bridge_to_api`'s tail answers STUBBED-true for everything — check the STATUS, not the boolean; only IMPLEMENTED handlers should preempt a loaded library), (b) the JNIEnv table must serve every slot the C body touches (F-C4-587: the object-array family — slot numbers are pinned by the jni.h struct layout: 171 GetArrayLength, 172 NewObjectArray, 173 GetObjectArrayElement, 174 SetObjectArrayElement), and (c) the HOST LINKER must not steal the library's own symbols (F-C4-595: an .so that statically links AND exports BoringSSL gets its internal `SSL_CTX_new` preempted by the host's libssl.so.3 — RTLD_DEEPBIND is the glibc analog of Android's linker namespaces). When a native "faults", do not stop at the guard: the SA_SIGINFO handler in this patch prints RIP + fault address + a maps-mapped stack walk — this wave's CB root was ONLY findable that way.
2. **Absolute paths are a DB-API surface (588):** Room/WorkManager pass `Configuration.name` as an ABSOLUTE Android path by design ("if it's an absolute path, that path is used"). Any storage API that does `base_dir / name` silently redirects absolute names to the HOST filesystem root when `name` is absolute (std::filesystem operator/ replaces the lhs). The ONE correct entry point is `resolve_android_path` — it owns the android→host mapping AND the caller-identity fence. The same law class explains the File ctor (589): OpenJDK's `resolve(parent, child)` ignores the parent when the child is absolute. Both bugs produced paths that "exist nowhere" — check for the `//` and mirror-segment spellings in traces.
3. **Thread identity is a DELIVERY property, not a global (593):** the engine's serialized model has one physical thread, but AOSP observability depends on WHICH virtual thread delivers a task: Handler.post on the main Looper → main identity (F-NEW-289, kept verbatim), Executor.execute → the POOL's worker identity. The queue entry must carry the identity (a `delivery_thread_id` field) and every drain binds it around run(). Room's assertNotMainThread, ArchTaskExecutor.isMainThread, and every `@WorkerThread` gate read exactly this observable. The per-executor Thread object must be FRESH (`heap_->allocate`), never `get_or_create` — that returns the main singleton and silently no-ops the whole law.
4. **Name-based stub gates rot (590/591):** two EXP-044/058-era gates ("collection iteration not supported", "constructor loop") were blocking androidx families whose iteration/ctor machinery has worked for many waves. The lawful stub criteria today: (i) a name gate may only target an app-specific spelling that would otherwise spin (the Telegram Emoji* gates stay), (ii) "iterates collections" is NEVER a justification, (iii) ctor refusal is never lawful (delegation is legal and bounded). When a census NPE names a field that "must have been set in a ctor", run `MINIANDROID_FIELD_TRACE=<field>` and check for the put-obj row — its absence + a STUB-ONLY log line is the gate signature.
5. **The deterministic device profile grows (592):** the runtime now answers "one active unmetered validated Wi-Fi network" — consistent with shipping a real TLS stack. The mask model (bit fields on the heap object + membership-test methods) extends to any capability/transport API without new machinery. Keep every constant's numbering EXACT (NET_CAPABILITY_INTERNET=12, TRANSPORT_WIFI=1 — app code compares literals).
6. **Corpus-neutrality as a design constraint (594's honest-fallback):** when promoting a new path (real natives), make the law never MANUFACTURE a new failure: on symbol-miss or guarded fault, restore the exact fail-soft observable the base binary answered. The battery re-run is maintainer-side as every wave; this constraint is what makes that re-run a formality instead of a risk.
7. **Disassembler discipline (tooling):** W10's dumpdex v2 was verified instruction-by-instruction against androguard on four format families after two real bugs (35c register operand from the wrong word; the 0x24..0x31 opcode range shifted by one — goto is 0x28, throw 0x27, fill-array-data 0x26, packed-switch 0x2b; a "goto/16 +0x71 landing past insns_size" is the shift's signature). When a PC attribution makes no sense, hexdump the raw units and hand-decode before theorizing.
