# ARTIFACT LIFECYCLE — REPOSITORY LAW (S-HYGIENE WAVE, permanent)

Status: **CANONICAL LAW** · Enforced by: `tools/check_repo_hygiene.py` (preflight/CI gate) ·
Registry: `docs/ARTIFACT_REGISTRY.json` (machine-readable, generated by
`tools/artifact_classifier.py`)

## 1. The lifecycle

Every generated artifact MUST move through this pipeline and MUST NOT stop in
the middle indefinitely:

```text
SOURCE → BUILD → EXECUTION → EVIDENCE → CANONICAL RECORD
                                    ↓
                             TEMPORARY ARTIFACT
                                    ↓
                                 DELETE
```

Formally:

```text
GENERATED → CLASSIFIED → USED → CANONICALIZED  or  DISCARDED
```

No artifact remains in the repository merely because nobody remembered to
delete it. **The default for unreferenced/generated residue is deletion.**

## 2. The retention question (ask in order)

For every large or generated artifact:

1. Is it source code?
2. Is it a canonical test fixture?
3. Is it a canonical evidence artifact?
4. Is it required to reproduce a documented result?
5. Is it referenced by a canonical registry / document / test?
6. Can it be deterministically regenerated?
7. Is there already another identical or stronger copy?
8. Is it merely an intermediate/debug/build/cache artifact?
9. Is it historical residue?
10. Is it only useful to a previous campaign and no longer needed?

If the answer chain reaches "no" for 1–5 and "yes" for any of 6–10 → **DELETE
IT** (record it in a ledger first; never delete silently).

Forbidden anti-patterns: compressing useless logs, optimizing useless APKs,
renaming useless dumps, archiving useless screenshots, keeping duplicate
evidence "just in case".

`binary ≠ unnecessary` and `generated ≠ automatically disposable` — the
distinction is **canonical vs non-canonical**, never binary vs text.

## 3. Artifact classes and retention rules

| Class | Meaning | Retention rule |
|---|---|---|
| `CANONICAL_SOURCE` | runtime C++/headers, build scripts, tools, games | KEEP (versioned) |
| `CANONICAL_FIXTURE` | .dex/.wav/.bin/golden/drawable test inputs | KEEP; each must be referenced by a test |
| `CANONICAL_EVIDENCE` | run records, screenshots/GIFs, traces, session reports, SHA manifests, registries | KEEP; each large item needs a registry/doc reference |
| `CANONICAL_DOC` | roadmap/README/ticket docs | KEEP |
| `REFERENCE_SOURCE_PINNED` | pinned upstream sources/jars | KEEP; record repo+version+license |
| `RAW_LOG` | raw terminal/session dumps | DELETE once facts are promoted to a canonical report/registry |
| `BUILD_ARTIFACT` | binaries, .o, build outputs, gmon/prof | DELETE (deterministically regenerable) |
| `CACHE` | download caches, corpus caches, toolchains | DELETE (external cache policy) |
| `TEMPORARY` | debug frames, probe outputs | DELETE at session end |
| `DUPLICATE` | byte-identical copies (SHA256) | DEDUPLICATE when references safely update; otherwise document |
| `OBSOLETE` | superseded by a newer canonical artifact | DELETE (record SHA in a ledger) |
| `UNKNOWN` | not yet classified | CLASSIFY or DELETE; do not accumulate |

A 30 MB terminal dump is NOT better evidence than a 2 KB deterministic record.
Canonical evidence = test identity + exact command + environment + result +
relevant trace + root cause + artifact SHA + reproducibility info.

## 4. Per-media retention policy

* **APK/AAB**: ZERO inside the repository, releases, or source ZIPs. APK
  identity = `upstream source + exact version/tag + SHA256 + retrieval
  metadata`. Deduplicate by SHA256. Only a canonical regression fixture APK may
  be referenced (external cache), never committed.
* **Screenshots/GIFs**: only canonical execution evidence + documented debug
  evidence survive; duplicates by SHA256 are detected each audit; intermediate
  frames and superseded captures are deleted.
* **Logs/traces**: delete raw dumps once the session report/registry holds the
  facts; distilled logs referenced by reports are evidence.
* **Build outputs/toolchains**: never committed; toolchain is re-obtained by
  `scripts/build/bootstrap_toolchain.sh`.
* **Source archives (handoff/backup ZIPs)**: a backup that violates GitHub
  limits is not repository content. Workspace backups are audited (see
  `docs/research/source-forensics/`), then deleted or externalized; they are
  never committed to Git.

## 5. Enforcement

`tools/check_repo_hygiene.py` fails preflight/CI when forbidden artifacts
appear: tracked APK/AAB, build directories, raw logs, oversize files, secret
patterns, new archive blobs. `tools/artifact_classifier.py` regenerates the
machine registry. Both are deterministic and dependency-free.

## 6. Precedent (S-HYGIENE wave, this law's origin)

The 621 MB `.git` was caused by the S78 accidental-snapshot quarantine branch
(151.0 MB workspace-backup ZIP + 75.7 MB compiled binary + caches = 593 MB
unique objects). Every unique blob was either rescued (ledger:
`docs/history/s78_quarantine_recovery/MANIFEST.json`) or explicitly disposed
with a class reason; the branch was then deleted and history was gc-pruned
(621 MB → 98 MB, zero history rewrite, zero canonical evidence destroyed).
