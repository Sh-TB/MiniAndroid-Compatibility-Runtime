## This Round's Progress

### F4 CRITICAL FIX: type_list entries are 2 bytes (ushort), not 4 bytes

**Root cause:** DEX format `type_item { ushort type_idx; }` — each entry is 2 bytes.
The runtime was reading 4 bytes per entry (`uint32_t`), which corrupted ALL proto
resolutions for methods with 2+ parameters.

**Impact on Telegram:**
- `$default$addFragmentToStack` proto resolved as `(J)Z` (takes long)
  instead of `(INavigationLayout;BaseFragment;)Z` (takes 2 objects)
- Wide-arg merger incorrectly merged the fragment argument as a long
- args_size=1 instead of 2 → fragment never passed → lifecycle never started

**Fix:** Changed 3 lines in `resolve_method_proto_for_dex()`:
- `* 4u` → `* 2u` (list_bytes calculation)
- `uint32_t` → `uint16_t` (type_idx variable)
- `i * 4` → `i * 2` (offset calculation)

**Result:** Fragment lifecycle NOW WORKS:
- `IntroActivity.onFragmentCreate()` executes (118 instructions)
- `LoginActivity.loadCurrentState()` executes (209 instructions)
- `getString(R.string.Page2Title..Page6Title)` called
- `addFragmentToStack` receives correct 2 args (ActionBarLayout + IntroActivity)
- Telegram completes with `Status: SUCCESS`
