**TicTacToe F-120 (root-caused from the law, generic fix shipped)**:
- Symptom: Button marks at cell top-left.
- Law: AOSP Button resolves `com.android.internal.R.attr.buttonStyle`
  (Button.java:221 in the fetched upstream file) → theme's Widget.Material.Button
  sets `android:gravity="center_horizontal|center_vertical"` (styles.xml, fetched);
  TextView constructor consumes the style bag. So `new Button(ctx)` answers
  CENTER gravity before any XML/DEX override.
- Engine defect: live text stage (execution_engine.cpp G36/G47 block) centers only
  when `text_gravity & 0x11`; ViewNode.text_gravity defaults 0; XML inflation only
  sets it when android:gravity is literally declared; nothing resolved the STYLE
  default. (Side-finding: `view_renderer.cpp`/`real_layout.cpp` are NOT in the
  Makefile source list — dead non-compiling code with an older gravity model;
  repo-hygiene item, no runtime effect.)
- Generic fix (F-120/R-NEW-387): resolve the style default once at node creation
  (`create_view`/`get_or_create_node`) for the center-gravity Button family
  (Button/ToggleButton/AppCompatButton/MaterialButton; CompoundButton children and
  ImageButton excluded — their styles differ upstream). Precedence preserved:
  XML android:gravity and DEX setGravity overwrite it later, as upstream.
- Reruns after fix: canvas probe byte-identical (no buttons — law-consistent);
  TicTacToe ×3 new deterministic frames with centered marks; battery 92/94 (only
  pre-existing environmental EXT-01/02) — zero regressions.
