# REPOSITORY HYGIENE POLICY (S59, Issue #386)

Scope: what may be tracked in Git, what must stay external, and how every
exception is approved and documented. This is the canonical policy referenced
by `tools/check_repo_hygiene.py` and `docs/ARTIFACT_LIFECYCLE.md`.

## Allowed categories (tracked)

| Category | Examples | Rule |
|---|---|---|
| Runtime + engine source | `miniandroid/src/**` | always allowed |
| Framework/base data | `miniandroid/framework_res/**` | required at every resource resolve; never treat as APK-derived payload |
| Canonical knowledge | `docs/foundation/**` registries, censuses, API matrix | curated, referenced, regenerated by committed recipes |
| Canonical evidence | `docs/evidence/<session>/`, `evidence/s<n>/` curated PNGs/JSON | one report + minimal artifacts per claim; raw traces stay external |
| Test fixtures | `miniandroid/test_apks/**` (DEX), `fixtures/**` SOURCE trees | intentional, small, documented; build OUTPUTS of fixtures are NOT tracked |
| Pinned dependencies | `upstream/**`, `tools/toolchain/**`, `tools/r8/**` | every file carries provenance (URL, version, license, SHA-256) in this doc or a ledger it links |
| Scripts/tools | `scripts/`, `tools/` (source only) | never commit caches or downloaded distributions under them |

## Forbidden in Git (hard law)

1. APK/AAB/`.so` payloads (zero-APK law §20).
2. Generated build outputs: `*.o`, `*.class` (outside the evidence allowance),
   `build/` trees, aapt2 intermediates (`res.zip`), `__pycache__/`, `*.pyc`,
   generated `R.java`/`classes.txt` copies.
3. Handoff/backup archives: `.zip`/`.7z`/`.tar.gz` — **no archive allowlist
   exists**; dependencies ship as extracted, pinned trees instead.
4. Raw logs outside the distilled-evidence whitelist; raw API dumps
   (`forensic_data/` exports stay curated — replacement tracked in #386).
5. Secrets/credentials (pre-commit secret guard is fail-closed).

## Oversize exceptions (>5 MiB, all provenanced in the checker)

`tools/toolchain/{aapt2,android-34.jar,r8.jar}`, `tools/android-34/android-34.jar`,
`tools/r8/r8.jar`, `upstream/cont12_maven/kotlinc-dist/**` (>5 MiB jars),
`upstream/{s43,s44}` pinned jars, `miniandroid/framework_res/resources.arsc`,
`miniandroid/src/dex/dalvik_engine.cpp`, canonical `docs/foundation/**` JSON.

**PENDING decision (do not silently externalize):** the pinned toolchain and
kotlinc-dist files stay tracked until a clean-room bootstrap is proven
(`scripts/build/bootstrap_toolchain.sh` recipe + #386 rule 5). Removing them
before that proof would break 8+ probe-build consumers and the regression
battery.

## Duplicate-path ledger

- `tools/android-34/android-34.jar` and `tools/toolchain/android-34.jar` are
  the SAME blob (Git stores it once). Canonical location: `tools/android-34/`.
  The `tools/toolchain/` copy is retained until consumers are re-pointed and
  re-verified in one reviewed batch (#386 C24).

## Measurement law

Working-tree bytes, fresh-checkout bytes, and `.git` bytes are separate
metrics and are never conflated. Checkout-path deduplication does NOT reduce
Git history storage; history rewrites are a separate, explicitly approved
migration (#386 rule 6).

## Checker self-test law (C28)

`tools/test_check_repo_hygiene.py` drives positive + negative cases against
synthetic path lists; any checker rule change must keep 22/22 green.
